# Brief: per-topic conductors for agent-mail (exploration and design)

Written 2026-10-31 by the agent-mail rollout session for the child session that owns this exploration. Read this first, then John's words below verbatim.

## John's request (2026-10-31, about 09:58 PDT, in the agent-mail session)

> There's another aspect to all of this coordination that I would like you to take into account and perhaps enhance: either the implementation or the skills that will surround the use of this implementation and the use of this MCP server.
>
> Right now, we're giving agent sessions the ability to communicate directly with each other so that we can have agent A working on one part of a task, agent B working on another part, and then the two of them can coordinate their work. However, it becomes hard to see the overall pattern of all the work when many agents are involved.
>
> What I'm thinking of is that we would use a single agent as a conductor. The majority of the time, although this doesn't have to be all of the time, whenever two agents want to communicate with each other, they should communicate through the conductor. Agent A will message agent B via the conductor so that the conductor can see the message and pass it along. This way, the conductor becomes aware of all of the traffic flowing between all of the agents and can see if there's any duplication happening, if anything is taking place that might conflict, and can also ensure that all of the work is harmonious to the purpose.
>
> Ideally, there will be one conductor per topic, so that, for example, all of the shared work machines can be doing model ingestion work, and they can all be managed by one conductor for that work. All of the work happening in my Nix configuration would be conducted by another one, and this would be separate from the Agent Deck conductor, who just looks over the health of all the sessions overall.
>
> These would be special agent mail conductors. Maybe even "conductor" isn't the right word. Maybe they should be called managers or foremen. Their job is to ensure consistency, ensure that the goal is remaining focused and everything is on track, and that no one is getting stuck and no one is being starved for work. If there are any questions being asked, then those questions can be proactively surfaced to the Agent Deck conductor rather than waiting for me to notice them.
>
> Create a workflow to explore this idea, and then work with me to create a good design for what we can add to Agent Mail to implement this as well.

And then: "If it works better for you to spin off a new agent deck session in a work tree to explore this idea, then let's do that." This session is that spin-off.
